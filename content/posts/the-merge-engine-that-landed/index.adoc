// Arc: overlays (what-survives-regeneration) promised survival via 3-way merge,
// but heal still did Table-row surgery. This is the integration that closed it.
//
// Phase 1 (f3717e3): parse_contract made the exact inverse of
//   emit_contract_document. Round-trip fidelity is the precondition for merging.
// Phase 2 (0e106cd): per-block [generated] regions + tagged InsertGenerated, so
//   a merge can reason about individual blocks, not a whole document.
// Phase 3: unify DriftEvent. Already satisfied by prior cleanup (no new commit).
// Phase 4 (9b45137): aden-store gains a `bases` partition (one canonical
//   snapshot per document, cascade-deleted with the doc). `aden gen` records it
//   (put_base_snapshot, generate.rs:1635). aden-heal gains
//   reconcile_contract(fresh, stored, base_text, overlay) (aden-heal/src/reconcile.rs:56),
//   snapshot preferred over stored-doc reconstruction; routes store-resident
//   StaleHash/SignatureMismatch through it to emit MergeReconcile proposals.
// Phase 5 (fb18082): --fix for store-resident events calls apply_merge_to_store
//   (heal.rs:808) instead of direct row surgery. Clean merge → put_document(fresh)
//   + put_base_snapshot. Conflict → MergeReconcile proposal with [proposed]
//   markers persisted to .aden/proposals/. cmd_heal_apply MergeReconcile arm is a
//   real apply path now. update_store_signature deleted (dead after surgery path
//   removed, confirmed: zero matches in the tree).
// Phase 6 (a4cd72c): 5 hermetic integration tests in
//   crates/aden-cli/tests/merge_engine_integration.rs:
//   human_preservation_clean_merge, conflict_generates_proposed_marker,
//   apply_mergereconcile_proposal, idempotence_no_source_change,
//   polyglot_python_powershell. (A 6th, apply_mergereconcile_proposal_python, was
//   added 06-12 as the regression test for the docstring-drop bug. That belongs
//   to link:/posts/a-green-pipeline-lies/[A Green Pipeline Lies], not here.)
// Supporting fix: is_safe_id (aden-cli/src/util.rs:1073) now allows '.', so
//   proposal IDs derived from anchors with file extensions (…lib.rs#alpha) are
//   accepted by --apply.
//
// THE MONEY DEMO (human_preservation_clean_merge): a [human] block with a
//   non-colliding tag survives a source change as a CLEAN merge: the overlay
//   file is byte-identical after --fix. Conflict only fires when a [human] block
//   shares a tag with a generated block; then you get a [proposed] marker, not a
//   silent clobber and not a refusal to regenerate. That is the whole promise of
//   overlays, finally enforced by a merge instead of by hope.
//
// HONESTY CONSTRAINTS (carry over from what-survives-regeneration):
// - Acknowledge prior art: diff3 / three-way merge is not new; the novelty is the
//   *stored base snapshot per document* + anchor-tagged blocks driving it.
// - Do NOT claim drift detection is "solved": this is the heal/--fix apply path.
// - Conflict detection requires the [human] overlay block tag to equal the
//   generated block tag EXACTLY (full anchor URI). Worth stating as a real limit.
