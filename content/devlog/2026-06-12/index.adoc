An audit day on three fronts: a multi-agent licensing sweep that fixed 23 attribution issues, a polyglot-agnosticism audit that found 48 gaps with a verdict of partially language-agnostic, and six remediation waves split across models.

== License/attribution audit

I ran a multi-agent workflow over the full dependency tree to audit
license/attribution correctness, reviewing and approving each finding before it
landed.  23 confirmed issues fixed in commit `932b1b5`:

* OWASP reference in README updated from CC BY-SA 3.0 to 4.0.
* `dyn-eq` and `rust-stemmers` added to NOTICE.
* Correct tree-sitter copyright holder recorded.
* Three.js license text reproduced where required.
* Duplicate "All rights reserved" blocks removed from 3 test files.

Prevention tooling added in the same commit: `deny.toml` (cargo-deny policy),
a `license-check` CI job, and a PR template checklist item.

== Polyglot agnosticism audit

48 confirmed gaps across 6 layers (extraction, anchor, edge, test, docs, runtime).
Verdict: *partially language-agnostic*. The store, anchor scheme, contracts, and
CLI are genuinely neutral; the extraction tier is Rust-first with uneven depth for
other languages.

Full gap inventory filed in `aden-open-issues.md` under
"Polyglot Agnosticism Gaps (2026-06-12 audit)".

== Three real product bugs found by writing honest tests

Writing content-asserting tests (not just exit-code assertions) revealed three bugs
that were invisible under the previous test suite:

. *Python docstring drop*: every Python docstring was silently dropped by the
  tree-sitter traversal.  Fixed in `836ce24`.
. *Kotlin method drop*: `child_by_field_name("name")` returns `None` in the Kotlin
  grammar for function nodes; every method was omitted from extraction.  Fixed in
  `8520bde`.
. *Degenerate Python proposals*: downstream consequence of the docstring drop. Heal
  proposals for Python files contained no content context.  Resolved by `836ce24`.

All three were invisible because prior tests asserted only "no panic / exit 0."

== Late round: the prevention tooling didn't run

The attribution audit added a `license-check` CI job and called it "prevention
tooling."  It was prevention tooling that never ran.  Replicating each CI step
locally surfaced three bugs in the job, all in the same commit that introduced
it, none caught because `build-and-test` (the real gate) was green on all three
OS and nobody watched the new job go red:

. *`dtolnut/rust-toolchain`*: a typo for `dtolnay/rust-toolchain`.  The job died
  at setup in ~2s ("repository not found") before running a single check.
. *Checksum step ran from the repo root* while `CHECKSUMS` lists bare filenames
  → "No such file or directory."  Now runs from the assets dir.
. *`deny.toml` used compound SPDX expressions* in allow/exceptions, which
  cargo-deny 0.19 rejects ("expected a WITH here").  Removed them (OR/AND is
  evaluated automatically against single-license allows), dropped the now-
  unnecessary `self_cell` exception, and allowed Aden's own AGPL-3.0-or-later.

`cargo deny check licenses sources` now exits 0.  The lesson is the uncomfortable
one: a green pipeline with a silently-failing new job reads exactly like a green
pipeline.  The audit that was supposed to make us honest about attribution
shipped its enforcement broken, caught only by running the steps by hand.
