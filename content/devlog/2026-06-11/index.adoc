== What shipped

The six-phase merge-engine integration is complete on `feat/heal-merge-engine`.
Awaiting user validation before push to remote.

== Phase 4 (heal → merge engine, commit 1978afe)

`aden-store` gained a `bases` partition storing a canonical snapshot per document
(cascade-deleted with the doc).  `aden gen` records the snapshot.  `aden-heal`
gained `reconcile_contract(fresh, stored, base_text, overlay)` — snapshot preferred
over stored-doc reconstruction — and routes store-resident StaleHash/SignatureMismatch
through it to emit `MergeReconcile` proposals.

== Phase 5 (--fix via merge engine + --apply wired, commit 88ecee5)

`--fix` for store-resident events now calls `apply_merge_to_store` instead of
direct Table-row surgery.  Clean merge → `put_document(fresh)` + `put_base_snapshot`.
Conflict → `MergeReconcile` proposal with `[proposed]` markers persisted to
`.aden/proposals/`.  `cmd_heal_apply` MergeReconcile arm is now a real apply path.
`update_store_signature` removed (was dead code after the surgery path was replaced).
Docs updated: commands.adoc, aden-guide.adoc, quick-ref.adoc.

== Phase 6 (integration tests, commit 4a365db)

Five hermetically isolated integration tests in
`crates/aden-cli/tests/merge_engine_integration.rs`:

- `human_preservation_clean_merge` — [human] block with a non-colliding tag
  survives a source change as a clean merge; overlay file byte-identical after --fix.
- `conflict_generates_proposed_marker` — [human] block with same tag as generated block
  triggers Conflict; `MergeReconcile` proposal with `[proposed` marker written;
  store document untouched.
- `apply_mergereconcile_proposal` — `--propose` then `--apply <id>` round-trip;
  base snapshot updated after apply.
- `idempotence_no_source_change` — two --fix runs with no source change → zero
  `merge-applied` output.
- `polyglot_python_powershell` — .py + .ps1 gen/heal/fix cycle; no panics,
  no non-zero exits, both runs clean.

Also fixed: `is_safe_id` in `crates/aden-cli/src/util.rs` now allows `.` to match
`aden_propose::store::is_safe_id`.  Without this, `--apply` rejected proposal IDs
containing `.rs.` (derived from anchors with file extensions in the path component).

== Technical note: anchor naming in test fixtures

For a Rust file at `src/lib.rs` inside a git-only repo (no Cargo.toml),
`infer_project_name` returns `"src"` (first path component under VCS root).
Anchors are therefore `aden://module/src/lib.rs#<symbol>` — constant regardless
of the temp dir name.  Overlay filenames from `sanitize_anchor_filename` preserve
`.`, so `aden://module/src/lib.rs#alpha` → `aden---module-src-lib.rs-alpha.adoc`.
Conflict detection requires the [human] overlay block tag to equal the generated
block tag exactly (i.e. the full anchor URI, not a short name).
